# Lite Llama NPU v0.0.3rc2

- 发布日期：2026-06-11
- 目标模型：Qwen3-30B-A3B
- 目标硬件：2 × Atlas 910B3
- 变更类型：Ascend Triton兼容性Bug修复

## 问题

v0.0.3rc1的专家Gather内核使用：

```python
target = tl.atomic_add(write_offsets_ptr + expert_id, 1)
```

其含义是原子递增专家写指针，并使用递增前的旧值作为当前任务的
目标位置。该写法在部分Triton后端可用，但Ascend Triton 3.2在
TTIR转Linalg阶段无法转换`atomic_add`的返回值，模型在内存探测
的首次前向中编译失败。

## 修复

新路径为：

```text
selected_experts
  -> NPU torch.argsort
  -> Triton ordered Gather
  -> Ascend Grouped MatMul
  -> Triton weighted Scatter
```

排序和Gather仍全部发生在NPU上，不引入Host同步。Triton Gather
使用`program_id`作为目标位置，仅从排序结果读取原assignment ID，
不再依赖原子操作返回值。

## 验证

本地验证：

- 19项Qwen3 MoE单元与接口契约测试通过；
- 回归测试明确禁止Gather kernel消费`tl.atomic_add`返回值；
- Python静态编译和`git diff --check`通过。

Atlas服务器先运行：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
ASCEND_RT_VISIBLE_DEVICES=6 \
python -m unittest tests.npu.test_qwen3_moe_gmm -v
```

通过后运行双卡逐层对齐：

```bash
export LITE_LLAMA_MOE_BACKEND=gmm
export LITE_LLAMA_MOE_VALIDATE=1

ASCEND_RT_VISIBLE_DEVICES=6,7 \
python -m torch.distributed.run --nproc_per_node=2 \
  cli_qwen3_moe_tp.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-30B-A3B/ \
  --page_size 16 \
  --max_seq_len 4096 \
  --max_gen_len 16 \
  --temperature 0 \
  --disable_thinking \
  --no_compiled_model
```

如果需要临时绕过GMM：

```bash
export LITE_LLAMA_MOE_BACKEND=eager
```
