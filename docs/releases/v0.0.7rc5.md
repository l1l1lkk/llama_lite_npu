# v0.0.7rc5 Release Report

Date: 2026-06-18

## Summary

`v0.0.7rc5` closes the practical KV-cache optimization pass for the v0.0.7 line. It upgrades the previous exact-prompt Prefix Cache into page-aligned partial prefix reuse and changes chunked prefill from an admission-only policy into a real multi-tick execution path.

## What changed

### Page-aligned partial prefix reuse

The live Prefix Cache can now reuse the longest cached page-aligned prefix of a greedy request.

```text
cached prompt:  A B C D | E F G H
new prompt:     A B C D | E F G H | X Y Z
reuse:          A B C D | E F G H
replay:         X Y Z
```

The backend shares cached Paged KV pages through page refcounts, then replays only the uncached suffix tokens. Exact-prompt hits still skip prefill entirely and reuse the cached first sampled token.

Current guardrails:

- enabled only for greedy requests (`temperature=0`);
- reuse is page-aligned, so sub-page prefixes are intentionally ignored;
- suffix replay uses the safe token-by-token decode path instead of an unsafe suffix-prefill kernel.

### True scheduler-visible chunked prefill

`--chunked_prefill --prefill_chunk_size <N>` now processes long prompts across multiple scheduler ticks. A long prompt no longer needs to wait until enough credit exists for the whole context.

This makes decode/prefill interleaving possible:

```text
tick 1: decode active requests + prefill long request chunk 0
tick 2: decode active requests + prefill long request chunk 1
tick 3: decode active requests + finish long request prefill
```

The implementation uses the same safe incremental token path as partial-prefix suffix replay. It is correctness-first and should primarily improve mixed long/short service responsiveness rather than raw single-request throughput.

### TP continuous-batching support

The TP CPU control channel now has a `prefill_chunk` command. Worker ranks reuse existing chunked-prefill request state across scheduler ticks instead of rebuilding request objects on each chunk.

### Mixed-length packed prefill status

`MixedLengthPrefillPacker` remains the tested metadata contract for future no-padding prefill kernels. The live model path still uses dense/equal-length prefill or safe incremental suffix replay. This release does not falsely claim a packed prefill kernel.

## Expected measurement behavior

Recommended tests:

1. Exact repeated prompt:
   - same prompt repeated;
   - `temperature=0`;
   - expect near-zero TTFT after first request.

2. Partial prefix reuse:
   - first request uses a shared system/history prefix;
   - later requests extend the same prefix with different suffixes;
   - expect lower TTFT than fully random prompts, but higher TTFT than exact prompt hits.

3. Chunked prefill responsiveness:
   - run at least one long prompt plus short prompts concurrently;
   - enable `--chunked_prefill --prefill_chunk_size <N> --max_prefill_tokens <N>`;
   - expect short requests to avoid waiting behind full long-prefill execution.

## Limitations

- Partial prefix replay is token-by-token for correctness; a future no-padding suffix-prefill kernel can make this faster.
- Prefix reuse remains disabled for sampling requests to preserve stochastic generation semantics.
- Mixed-length packed prefill is not yet connected to the attention kernel.
- No Atlas performance number is recorded for this release yet.
