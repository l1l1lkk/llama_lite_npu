# v0.0.8rc1 Release Report

Date: 2026-06-18
Branch: `release/0.0.8rc1`

## Summary

`v0.0.8rc1` moves the continuous-batching prefill path from metadata-only planning toward live execution:

- mixed-length cache misses are packed into one flattened prefill forward;
- PagedAttention metadata now represents logical request boundaries through `b_start_loc` and `b_seq_len` while model input stays no-padding flattened;
- chunked prefill replay batches requests by token step instead of running a Python loop per request.

## What changed

### Mixed-length packed prefill

Before this release, continuous batching grouped prefill requests by equal prompt length. A batch containing prompt lengths `[184, 156, 120]` could produce multiple prefill forwards.

In this release, cache-miss requests with different prompt lengths are flattened into a single model input:

```text
request A: [a0, a1]
request B: [b0]
request C: [c0, c1, c2]

flat input:      [a0, a1, b0, c0, c1, c2]
b_start_loc:     [0, 2, 3]
b_seq_len:       [2, 1, 3]
sample_indices:  [1, 2, 5]
```

The logits used for sampling are gathered from `sample_indices`, one row per logical request.

### Chunked prefill replay

`--chunked_prefill` still prioritizes correctness over maximum raw prefill throughput because the project does not yet have a dedicated suffix-prefill attention kernel. However, replay is now batched across active prefilling requests at each token step, reducing Python overhead and improving small-batch utilization when multiple prompts are chunking at the same time.

## Expected performance impact

This version should mainly affect server workloads with heterogeneous prompt lengths or multiple concurrent long prompts:

- lower TTFT for mixed-length concurrent prefill;
- fewer model forwards for mixed prompt batches;
- lower Python overhead for chunk replay with multiple active prefills.

It is not expected to materially improve single-request decode ITL/TPOT.

## Known limitations

- No dedicated chunked suffix-prefill attention kernel yet.
- Partial Prefix Cache remains opt-in via `--partial_prefix_cache`.
- No new Atlas 910B3 performance number is recorded in this release report. Update `docs/inference_performance_history.md` after real server/EvalScope testing.
