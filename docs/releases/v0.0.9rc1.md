# v0.0.9rc1 Release Report

Date: 2026-06-23

## Summary

`v0.0.9rc1` improves the Chunked Prefill execution path by routing the first chunk through the existing packed-prefill path. For Qwen3/Qwen2/Llama text models this means the first chunk reuses `flash_attention2_no_pad` instead of replaying one token at a time through the decode path.

Later chunks intentionally keep the existing incremental fallback. The current `flash_attention2_no_pad` kernel computes full-context causal attention over the current flat Q/K/V buffer; it cannot attend to historical paged KV. Using it directly for non-first chunks would be faster but numerically wrong.

## Changes

- Added a first-chunk packed-prefill fast path for Chunked Prefill.
- Preserved the safe incremental fallback for later chunks.
- Added one-shot runtime logging of effective prefill attention paths:
  - full prefill: `flash_attention2_no_pad`
  - packed prefill: `flash_attention2_no_pad`
  - chunked first chunk: `flash_attention2_no_pad`
  - chunked later chunks: `paged_chunk_flash_attention` if available, otherwise incremental fallback
- Added regression coverage for first-chunk fast path selection and later-chunk fallback behavior.

## Expected Impact

This release removes the worst unnecessary overhead for the first Chunked Prefill slice. It does not yet make Chunked Prefill competitive for long prompts, because later chunks still replay incrementally.

The next real performance step is a dedicated paged chunk prefill attention kernel:

```text
Q: current chunk tokens
K/V: historical paged KV + current chunk K/V
Output: current chunk hidden states
```

## Known Limits

- Chunked Prefill remains experimental and should stay off by default for performance-critical runs until later chunks use a true paged chunk FlashAttention kernel.
- The existing no-pad FlashAttention kernel is correct for full/packed prefill and the first chunk only.
