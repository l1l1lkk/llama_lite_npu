# v0.0.12rc3 发布记录

## 版本定位

v0.0.12rc3 是服务器实测阶段发现的问题修复版本，不改变 v0.0.11rc1 和 v0.0.12rc1 的优化目标。

## 问题描述

Top-P 并发 4 实测时，服务端在 TP worker 上崩溃：

```text
RuntimeError: Tensors must be contiguous
```

报错位置在 Decode 采样路径的 HCCL `all_gather`：

```text
lite_llama/sampling.py::_all_gather_stack
```

## 排查过程

Greedy 单并发可以正常完成，说明模型加载、NPU Graph、Continuous Batching 和基础通信链路正常。

Top-P 并发 4 在采样阶段触发候选 token 的 batched all-gather。该路径会从 `topk`、索引、切片等操作得到候选 logits 和 token ids，其中部分 tensor 在 NPU 上可能是 view 或非连续布局。

CPU 单测中 mock collectives 对 tensor layout 不敏感，因此没有暴露问题；HCCL 对 `all_gather` 输入更严格，要求输入 tensor 是 contiguous。

## 修复方式

在 `_all_gather_stack()` 的 collective 边界统一处理：

```python
if not tensor.is_contiguous():
    tensor = tensor.contiguous()
```

这样调用方不需要分别关心每一种候选 tensor 的来源，也避免后续新增采样路径再次踩同类问题。

## 验证

- 新增非连续 tensor 回归测试，模拟 HCCL 对 contiguous 的要求。
- 本地单测通过。
- 服务器容器内单测通过后，继续执行 Top-P 并发实测。
