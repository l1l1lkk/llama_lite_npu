# v0.0.7rc4 Release Report

Date: 2026-06-17

## Summary

`v0.0.7rc4` turns part of the scheduler/KV foundation into a runtime-visible optimization. The release adds exact-prompt live Prefix Cache for greedy requests and improves chunked-prefill scheduling so short prompts are not forced to wait behind long prompts in the admission queue.

## What changed

### Exact-prompt live Prefix Cache

For greedy requests (`temperature=0`), the backend now stores an exact prompt cache entry after prefill:

```text
prompt token ids -> Paged KV pages + prompt length + first sampled token
```

When the same prompt appears again, the backend:

1. Reserves a new request id.
2. Shares the cached KV pages by increasing page refcounts.
3. Restores the first sampled token on device.
4. Skips the prefill model forward.
5. Enters normal decode.

This gives a directly measurable TTFT reduction for repeated exact prompts.

### Sampling correctness guard

Prefix Cache is disabled for `temperature > 0`. Caching the first sampled token would otherwise change stochastic generation semantics. Top-P/random requests keep the original prefill path.

### Paged KV page sharing

`PagedReqTokensManager` now supports request creation from existing page ids. It uses the page refcount support added in rc3, so cached/shared pages remain alive until all references are released.

### Bounded cache ownership

The executor keeps a bounded LRU cache for exact prompt entries. Evicted entries release their cache-held page references.

### Chunked-prefill scheduling interleaving

When chunked prefill is enabled, long prompts accumulate prefill credit in `prefill_chunk_size` increments. Until enough credit is available, they can be rotated behind shorter prompts. This does not run unsafe suffix-prefill kernels; it is a conservative scheduling improvement intended to reduce short-request waiting behind long prompts.

## Expected measurement behavior

Use two separate tests:

1. Repeated exact greedy prompt test:
   - same prompt repeated many times;
   - `temperature=0`;
   - expect TTFT to drop after first request.

2. Mixed long/short prompt concurrency test:
   - one or more long prompts plus short prompts;
   - enable `--chunked_prefill --prefill_chunk_size <N> --max_prefill_tokens <N>`;
   - expect short request latency to improve.

Do not expect gains on random prompt datasets with no repeated prefixes.

## Remaining work

- Partial-prefix KV reuse where prompt B extends prompt A.
- True chunked/suffix prefill execution.
- Copy-on-write page sharing for non-greedy or divergent generation.
- Prefix Cache metrics in server responses or Prometheus-style telemetry.
