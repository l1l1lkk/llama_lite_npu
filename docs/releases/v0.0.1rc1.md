# Lite Llama NPU v0.0.1rc1

- 发布日期：2026-06-09
- Git Tag：`v0.0.1rc1`
- 模型：Qwen3-32B
- 硬件：2 × Atlas 910B3
- 精度：FP16
- 并行方式：TP=2

## 版本定位

`0.0.1rc1`是项目首个带版本号的候选版本，建立当前推理能力、正确性和性能基线。由于此前没有正式版本，本报告以NPU Graph修复前的最近一次EvalScope结果作为内部性能对照。

## 本次更新

### NPU Graph Decode Replay

- 使用`torch.npu.NPUGraph()`和`torch.npu.graph(...)`官方接口；
- 移除当前torch_npu版本不支持的`ACL_TASK_SINK`选项；
- 按`(batch_size, 128-token sequence bucket)`缓存Decode Graph；
- 同一长度Bucket内更新输入Token、Position、KV写入索引和实际序列长度后直接Replay；
- 移除Replay路径中的逐Token全局同步；
- 捕图失败的Shape进入黑名单，避免每个Token重复Capture。

### Paged KV增量更新

- Prefill阶段首次建立完整Token映射；
- Decode阶段只写入新增Token的逻辑位置到物理KV位置映射；
- 仅在跨Page边界时分配新Page；
- 移除随上下文增长的全表重建和`page_id.item()`同步路径。

### OpenAI API与评测

- 流式接口支持`stream_options.include_usage`；
- 在`[DONE]`前返回真实`prompt_tokens`、`completion_tokens`和`total_tokens`；
- EvalScope能够正确统计完整Qwen3 ChatML输入长度。

## 正确性验证

使用`temperature=0`分别运行Graph和Eager模式，覆盖：

1. 短输出，主要覆盖128-token Bucket；
2. 长输出，跨越128、256和384等Bucket；
3. 长Prompt，从较大的上下文Bucket开始。

每个用例重复三次，Graph模式内部输出稳定；Graph与Eager输出完整一致。该验证排除了Graph复用旧Logits或跨Bucket错误复用的主要风险。

## EvalScope性能

### Lite Llama NPU 0.0.1rc1

测试条件：

- 15个请求，并发1；
- 随机原始输入长度20～45 tokens；
- 完整ChatML输入平均59.53 tokens；
- `max_tokens=2048`；
- 真实SSE Streaming；
- 平均输出494.47 tokens。

| Test Duration | 308.263 s |
| 平均延迟 | 20.5502 s |
| TTFT | 261.2 ms |
| TPOT | 40.6 ms |
| ITL | 40.9 ms |

| Total Throughput | 26.9575 tok/s |

## vLLM-Ascend对比基座

基座采用第三方公开的vLLM-Ascend 0.8.4rc2结果：

- 2 × Atlas 910B3；
- Qwen3-32B；
- BF16；
- TP=2，并发1；
- Output Throughput：`7.6409 tok/s`；
- Total Throughput：`7.8122 tok/s`；
- TTFT：`392.7 ms`；
- TPOT：`131.1 ms`。

| 指标 | Lite Llama NPU 0.0.1rc1 | vLLM-Ascend 0.8.4rc2 | 对比 |
|---|---:|---:|---:|
| Output Throughput | 24.0606 tok/s | 7.6409 tok/s | 本项目约3.15× |
| Total Throughput | 26.9575 tok/s | 7.8122 tok/s | 本项目约3.45× |

| TTFT | 261.2 ms | 392.7 ms | 本项目低约33.5% |

该对比不是严格同口径Benchmark：双方计算精度、输入模板、平均输入长度、平均输出长度和EvalScope版本可能不同。当前结果用于工程基座观察，不应解释为框架间的最终性能结论。

## 已知限制

- 服务端TP模式仍是单请求串行执行，尚未实现Continuous Batching；
- 每个Decode Token仍有大量small-M MatMul和同步HCCL通信；
- Q+KV、Gate+Up尚未融合；
- LM Head仍AllGather完整词表Logits；
- NPU Graph会在进入新的128-token Bucket时首次Capture，可能产生一次性延迟；
- vLLM-Ascend对比数据来自第三方，尚未完成严格同环境复测。
