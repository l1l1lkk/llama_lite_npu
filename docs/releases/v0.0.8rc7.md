# v0.0.8rc7 Release Report

Date: 2026-06-22

## Scope

`v0.0.8rc7` is a bugfix release for server-side `max_seq_len` configuration propagation.

## Problem

`v0.0.8rc6` added correct context-length admission checks, but the server entrypoint still did not expose `--max_seq_len`. As a result, text server runs always used `GenerateStreamText`'s default `max_seq_len=1024`.

Trying to start the server with a larger context failed:

```text
server.py: error: unrecognized arguments: --max_seq_len 2048
```

## Root cause

The model/generator stack already supported `max_seq_len`, but the server CLI did not pass it through:

```text
server.py CLI
  -> load_generator(...)
  -> GenerateStreamText(...)
  -> ModelExecutor.build(... max_seq_len=...)
```

The missing link was the server entrypoint.

## Changes

- Added `server.py --max_seq_len`, defaulting to `1024` to preserve existing behavior.
- Passed `max_seq_len` into `GenerateStreamText`.
- Passed `max_seq_len` into `Qwen3VLGeneratorStream` for consistency.
- Printed `Max seq len` in startup logs.
- Added server contract tests to ensure the argument stays wired.

## Validation

Local validation:

```bash
git diff --check
python -m py_compile server.py tests/test_server_batching.py
python -m unittest tests.test_server_batching tests.test_continuous_batching tests.test_tp_control -v
```

All 43 related tests passed in the development environment.

## Operational note

For EvalScope tests with random prompts up to 1024 tokens and `--max-tokens 128`, start the server with at least:

```bash
--max_seq_len 2048
```

This keeps the request within the continuous-batching context guard after tokenizer/chat-template expansion.
