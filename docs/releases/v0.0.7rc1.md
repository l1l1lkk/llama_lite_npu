# v0.0.7rc1 Release Notes

Date: 2026-06-17

## Summary

v0.0.7rc1 is the first scheduler and KV-engine refactor release. It does not claim new Atlas throughput yet. The goal is to move continuous batching from pure request-count admission toward token-budget scheduling, and to add the metadata foundations needed for prefix cache, chunked prefill, and future KV preemption.

## Changes

### Scheduler

- `ContinuousBatchScheduler` adds `max_prefill_tokens` to limit prompt tokens admitted into one scheduler tick.
- Oversized prompt anti-starvation: a single request larger than the budget can still be admitted alone.
- `ContinuousBatchScheduler` adds `max_decode_tokens` to limit active decode rows per scheduler tick.
- Default behavior remains compatible: when budgets are omitted, scheduling still follows `max_batch_size`.

### KV engine metadata

- Added `lite_llama.kv_engine.KVBlockRefCounter` for CPU-side logical KV block reference counting.
- Added `PrefixCache` for block-aligned longest-prefix matching. This is metadata only in v0.0.7rc1 and is not yet wired into live PagedAttention KV reuse.
- Added `ChunkedPrefillPlanner` to split prompt lengths into fixed prefill chunks for later decode/prefill interleaving.

### Server CLI

New continuous batching controls:

```bash
--max_prefill_tokens INT
--max_decode_tokens INT
--chunked_prefill
--prefill_chunk_size INT
```

`--chunked_prefill` is experimental and disabled by default.

## Verification

- `tests.test_continuous_batching` covers token-budget admission, oversized prompt handling, decode budget, and existing continuous batching behavior.
- `tests.test_kv_engine` covers KV refcounting, prefix matching, and chunk planning.
- No predicted performance numbers are added. Atlas 910B3 results should be recorded after measurement.

## Known limitations

- Prefix cache is not connected to live PagedAttention KV reuse yet.
- Chunked prefill is a planning/configuration entry, not a full execution path yet.
- KV shortage preemption/recompute is not implemented yet.
- Mixed-length packed prefill is not implemented yet.
