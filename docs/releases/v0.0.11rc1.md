# v0.0.11rc1 Release Report

## 版本定位

v0.0.11rc1 聚焦 Decode 热路径中的采样阶段。目标是在 Tensor Parallel 词表切分场景下减少 Top-P 采样的通信次数，并把采样 fallback 行为暴露到 Prometheus，方便后续用实测数据判断 logits 层是否仍是瓶颈。

## 主要更新

- 新增批量 vocab-parallel Top-P 候选采样路径。
- Greedy 路径继续只交换每个 rank 的局部最大候选，不聚合完整词表 logits。
- Top-P 路径按 batch 一次性交换每 rank 的 top-k 候选。
- 当候选集合无法严格证明包含完整 nucleus 时，保留完整 logits gather 作为正确性 fallback。
- 新增 `--sampling_candidate_k`，用于控制每 rank Top-P 候选数量。
- 新增采样路径 Prometheus 指标：
  - `lite_llama_sampling_candidate_rows_total`
  - `lite_llama_sampling_fallback_rows_total`
  - `lite_llama_sampling_full_logit_gather_batches_total`

## 为什么这样做

Top-P 采样不能简单只看局部 top-k，因为全局 softmax 分母来自所有 rank。新实现先用 all-reduce 得到每行全局最大值和全局 exp sum，再用候选集合判断 nucleus 是否完整。只有无法证明完整时才进入完整 logits gather。这保持了正确性，同时减少常见场景下的词表通信。

- full-logit fallback 计数。
- Prometheus 采样计数器导出。

## 服务器验证计划

在服务器容器内更新代码后执行：

```bash
curl -s http://127.0.0.1:8213/metrics | grep lite_llama_sampling
```

随后分别运行 Greedy 与 Top-P EvalScope。重点观察：

- Top-P 的 output throughput。
- `lite_llama_sampling_fallback_rows_total` 是否过高。
- 调大 `--sampling_candidate_k` 后 fallback 是否下降。
