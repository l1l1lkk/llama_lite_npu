# v0.0.13rc3 发布记录

发布日期：2026-07-13

## 版本定位

v0.0.13rc3 是固定输出长度控制与严格 benchmark 可复现性版本。任务1新增了公开 `min_tokens` 请求字段、逐请求 EOS mask、Tensor Parallel 控制面字段和采样语义；该能力属于小功能，依据 [`docs/versioning.md`](../versioning.md) 从 v0.0.13rc2 提升 RC 到 v0.0.13rc3。任务2仅补充严格测试、数据和文档，本身不单独触发升版。

本项目的版本规范没有要求每个 tag 新建 release 分支，v0.0.13 系列 tag 也沿用 `release/0.0.12rc1`。本版本继续使用该分支，不创建或重命名分支。

## 新增功能

OpenAI-compatible chat/completion schema 新增可选 `min_tokens`：

- 默认值为 0，未传时保持旧行为；
- 负值以及 `min_tokens > max_tokens` 在请求边界被拒绝；
- batch 内不同请求可以使用不同阈值；
- greedy 与 Top-P 共用采样前 EOS mask；
- 达到 `min_tokens` 后恢复 EOS，仍可正常以 `stop` 结束；
- 未硬编码模型或 EOS token ID。

## 请求与采样调用链

```text
OpenAI ChatCompletionRequest / CompletionRequest
  -> server endpoint handler
  -> _submit_continuous_request
  -> ContinuousBatchScheduler.submit
  -> BatchRequest(min_tokens, sampled_token_count)
  -> TP prefill control message（逐请求同步 min_tokens）
  -> ContinuousBatchModelBackend._sample_device
  -> sample_next_token
  -> 按 batch row 和本 rank vocab shard 在采样前屏蔽 EOS logit
```

rank 0 与 worker rank 使用同一请求阈值并同步递增 `sampled_token_count`。只有持有全局 EOS token 对应本地 vocab 列的 rank 修改该列，保证 TP rank 行为一致。

没有采用“采到 EOS 后忽略并继续循环”的方案，因为该方案已经选择了 EOS，可能产生重复 EOS、空文本和错误的增量解码状态。

## 正确性验证

测试覆盖：

- chat/completion schema 默认值和输入边界；
- streaming 与非 streaming 参数透传；
- batch 内逐请求不同 `min_tokens`；
- greedy 采样前逐行 EOS mask；
- EOS token 的全局/TP shard 本地列换算；
- `min_tokens=0` 兼容行为；
- 达到阈值后 EOS 正常停止；
- TP prefill 控制消息往返一致性。

## 严格 NPU Graph on/off 消融

workload 固定为 Qwen3-32B、TP=2、FP16、prompt 128、固定 greedy 输出 256。Graph on/off 对使用相同正式请求数、warmup、seed、dataset offset、冻结 JSONL、prompt token 序列及 EvalScope 参数，并使用独立服务生命周期。每个模式在 concurrency 1 和 4 各运行三轮，12/12 formal run 均满足 input=128、output=256、0 failed。

延迟 ratio 为 `off/on`，吞吐 ratio 为 `on/off`：

| 并发 | E2E ratio | TPOT ratio | ITL ratio | Output throughput ratio | E2E 降低 | 输出吞吐提升 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 4.8624× | 5.0226× | 5.0229× | 4.8621× | 79.43% | 386.21% |
| 4 | 4.5802× | 4.6612× | 4.6613× | 4.5580× | 78.17% | 355.80% |

Graph on 在正式计数前完成 capture，正式区间 capture 增量和 fallback 均为 0；Graph off 的 capture attempts、capture、replay、fallback 全为 0。c1 TTFT 基本不变，c4 的高 TTFT 与 queue wait 留待后续专项分析。本表是项目自身 Graph on/off 消融，不是与 vLLM-Ascend 的对比。

## 已知限制

- 非 Continuous-Batching 的旧生成器路径尚未接入公开 `min_tokens`。
- 当前固定输出实测只覆盖 Continuous Batching 文本端点、Qwen3-32B、TP=2、FP16。
- 高并发 TTFT 与 queue wait 尚未完成根因分析，留待下一 benchmark 阶段。
- Graph 消融结论仅适用于报告中的短 prompt、固定输出和当前软件栈，不外推到其他模型、上下文长度、精度或外部推理引擎。
