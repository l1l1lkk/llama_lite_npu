# v0.0.8rc2 Release Report

Date: 2026-06-22
Branch: `release/0.0.8rc2`

## Summary

`v0.0.8rc2` fixes a chunked-prefill KV allocation bug found during EvalScope/server testing of the v0.0.8 packed-prefill line.

The failure happened when chunked prefill initialized each request with only one logical token of KV capacity, then attempted to allocate additional Paged KV pages while replaying the prompt. Under longer prompts, concurrent requests, and cached-page refcounts, this could fail mid-replay and crash a TP worker rank.

## What changed

### Logical length and reserved KV capacity are now separate

Paged KV request allocation now supports reserving physical capacity independently from the logical sequence length visible to attention:

```text
logical seq len: current replayed tokens visible to attention
reserved tokens: physical KV page capacity reserved for the whole request
```

New/extended APIs:

- `PagedReqTokensManager.reserve_req(num_tokens, reserved_tokens=None)`
- `PagedReqTokensManager.ensure_req_capacity(req_idx, total_tokens)`
- `ModelExecutor.reserve_paged_requests(..., reserved_lengths=None)`
- `ModelExecutor.ensure_paged_request_capacity(...)`

### Chunked prefill reserves capacity up front

For chunked prefill, the backend now reserves capacity for:

```text
len(prompt_tokens) + 1
```

The `+1` is the first generated-token slot after prefill. The logical token count still starts at one token and advances incrementally during replay, so attention does not read uninitialized KV positions.

### Partial prefix suffix replay capacity

When partial Prefix Cache is enabled and a page-aligned cached prefix is reused, the uncached suffix replay also ensures full prompt KV capacity before incremental replay starts.

## Expected performance impact

This is a correctness/stability bugfix. It should not materially change decode ITL or steady-state throughput. It should make `--chunked_prefill` stable for longer prompts and concurrent mixed prefill workloads.

## Known limitations

- Chunked prefill still uses correctness-first incremental replay; no dedicated suffix-prefill attention kernel exists yet.
- Partial Prefix Cache remains opt-in via `--partial_prefix_cache`.
- This release does not claim a new Atlas performance number beyond the recorded v0.0.8rc1 measurements.
