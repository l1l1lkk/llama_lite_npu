# v0.0.8rc4 Release Report

Date: 2026-06-22
Branch: `release/0.0.8rc4`

## Summary

`v0.0.8rc4` fixes a TP continuous-batching state synchronization bug observed after `v0.0.8rc3`:

```text
RuntimeError: unknown continuous batching control_id: 19
```

The previous fixes moved chunked-prefill capacity checks earlier, but rank 0 could still partially prepare local request state without a durable worker-side mirror. A later decode command could then target a control id that rank 1 had never created or had already released.

## What changed

### Rank-0 worker-known control-id tracking

`_TpCoordinatedContinuousBackend` now tracks which `control_id`s have been mirrored to worker ranks through `prefill` or `prefill_chunk` commands.

Before sending a decode command, rank 0 verifies every request is known by workers. If not, it raises a rank-0 error instead of sending a decode that would crash rank 1.

### Rollback for failed chunked-prefill prepare

If `prepare_prefill_chunk(...)` fails before the worker command is sent, newly allocated local request ids are released and restored. This prevents half-initialized local requests from leaking into later scheduler ticks.

### Idempotent worker release

Worker ranks now ignore release commands for unknown control ids. Release is cleanup; it must be safe even if the worker never saw the corresponding create command or already removed the request.

## Expected performance impact

This is a correctness/stability fix. It should not materially change throughput. It should prevent TP worker crashes caused by decode commands for unknown `control_id`s.

## Validation

Validated locally with:

```bash
python -m unittest tests.test_server_batching tests.test_continuous_batching -v
python -m py_compile server.py tests/test_server_batching.py
```

Server-side validation should rerun the failed chunked-prefill test and verify rank 1 no longer exits with `unknown continuous batching control_id`.
