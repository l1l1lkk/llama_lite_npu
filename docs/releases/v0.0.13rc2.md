# v0.0.13rc2 发布记录

## 版本定位

v0.0.13rc2 是 v0.0.13rc1 的验证兼容性修复版本，同时补充服务器端 decode-priority 调度 A/B 实测。该版本不改变 v0.0.13rc1 已引入的调度语义。

## 修复内容

服务器容器运行：

```bash
python scripts/validate_release.py
```

时，`unittest discover` 会导入 `tests/test_torch_matmul.py`。该文件是可选的矩阵乘可视化 benchmark，导入时依赖 `matplotlib`。推理容器没有安装 `matplotlib`，导致发布验证被可选绘图依赖阻断。

修复方式：当 `matplotlib` 缺失时，将该文件标记为 `unittest.SkipTest`。这样核心测试仍会执行，可选可视化测试在缺少依赖时被跳过。

## Decode Priority A/B 实测

测试命令为 EvalScope random 数据集，40 个请求，并发 4，平均输入 178 tokens，`temperature=0.6`，`top_p=0.9`，流式输出。

| 模式 | 输出吞吐 | 总吞吐 | 平均延迟 | TTFT | TPOT | ITL | 成功 |
|---|---:|---:|---:|---:|---:|---:|---:|
| `--decode_priority` | 39.00 tok/s | 66.13 tok/s | 25.88 s | 13.438 s | 48.82 ms | 48.73 ms | 40 / 40 |
| `--no_decode_priority` | 56.06 tok/s | 97.42 tok/s | 16.59 s | 1.889 s | 61.66 ms | 61.21 ms | 40 / 40 |

结论：decode priority 会让活跃 decode 请求更少被新 prefill 打断，使 ITL 和 TPOT 下降约 20%；代价是新请求 prefill 被主动延后，TTFT 和总吞吐变差。该策略适合作为在线服务默认值；离线吞吐压测可以关闭。
