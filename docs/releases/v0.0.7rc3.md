# v0.0.7rc3 Release Report

Date: 2026-06-17

## Summary

`v0.0.7rc3` completes the safe runtime pieces that were still missing from the v0.0.7 scheduler/KV-engine refactor. The release focuses on KV lifecycle correctness and preemption under KV pressure, while keeping no-padding packed prefill and live prefix-cache reuse behind explicit foundation APIs instead of enabling unsafe partial execution.

## What changed

### KV-pressure preemption

Continuous batching can now recover from KV capacity pressure instead of failing the whole active batch immediately. When the backend raises `KVCacheCapacityError` or a recognized KV allocation/capacity error, the scheduler:

1. Requeues the not-yet-committed newly admitted requests.
2. Selects one active victim with the longest live context.
3. Releases the victim KV pages.
4. Requeues the victim.
5. Rebuilds the victim context from:

```text
prompt_tokens + generated_token_ids
```

This avoids emitting duplicate streamed tokens after recompute.

New option:

```bash
--max_preemptions 1
```

Set `--max_preemptions 0` to disable this behavior.

### Paged KV reference counts

`PagedKVCacheManager` now tracks Host-side page reference counts. A page is only returned to the free pool when the last reference is released. This is required for correct future Prefix Cache and shared-KV behavior.

Added request page introspection:

```python
PagedReqTokensManager.request_pages(req_idx)
```

### Mixed-length and chunked prefill contracts

Added `MixedLengthPrefillPacker`, which produces flattened token and position metadata for future no-padding prefill kernels. The existing `ChunkedPrefillPlanner` remains the chunk contract.

The runtime does **not** claim true packed/chunked prefill execution yet, because the current model path still expects dense `[batch, seq]` tensors and the Attention/KV writer path must be changed together to preserve correctness.


Result: 56 unit tests passed.

## Expected performance impact

No direct single-request throughput improvement is expected from this release. The value is stability and capacity behavior under continuous batching:

- fewer whole-batch failures when KV is tight;
- safer future prefix-cache implementation;
- clearer contract for no-padding packed prefill and chunked prefill.

## Remaining v0.0.7 work

Still not live in the model execution path:

- true no-padding mixed-length prefill;
- suffix/chunked prefill execution against existing KV;
- live Prefix Cache reuse;
- KV preemption policy with swap/offload; current strategy is recompute-based.
