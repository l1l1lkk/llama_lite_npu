# Lite Llama NPU v0.0.5rc1

- 发布日期：2026-06-11
- 目标模型：Qwen3-30B-A3B、Qwen3 Dense文本模型
- 目标硬件：Atlas 910B3
- 变更类型：调度、MoE Decode内核与并行策略

## 相对v0.0.4rc1的变化

### P7：Continuous Batching

文本Server新增共享后台调度器。新请求可在已有请求Decode期间加入活动Batch，每个请求拥有
独立Paged KV request ID、序列长度、最大输出长度和输出队列。

不同长度Prompt首版按长度分组Prefill；Decode允许不同上下文长度的请求组成动态Batch。
TP rank 0广播步骤级命令，其他Rank执行相同Prefill、Decode和Release。

新增参数：

```text
--continuous_batching / --no_continuous_batching
--max_batch_size
--max_waiting_requests
--scheduler_poll_ms
```

该路径当前只接入文本Server，VL继续使用原有请求级执行。

### P8：Decode小Batch专家内核

新增`routed_gemv`后端，直接按token/top-k assignment执行Gate/Up、SwiGLU、Down和
TopK归约，不经过通用专家排序、Gather和Scatter。

自动选择规则：

```text
tokens * top_k <= 64 -> routed_gemv
其他NPU批次             -> Ascend GMM
CPU                     -> eager reference
```

阈值可通过`LITE_LLAMA_MOE_GEMV_MAX_ASSIGNMENTS`设置。后端可通过
`LITE_LLAMA_MOE_BACKEND=auto|eager|gmm|routed_gemv`强制选择。

### P9：Expert Parallel

现有Attention TP会在MoE前复制每个Rank的hidden states，因此EP采用本地专家计算加
一次AllReduce，不增加All-to-All：

```text
每Rank相同hidden states
 -> 只计算本Rank持有的完整专家
 -> HCCL AllReduce合并各Rank局部token输出
```

`--moe_parallel_mode tp`保持原有“每个专家内部切分”；`ep`改为“完整专家按Rank切分”。
Router继续复制，Checkpoint格式不变。

## 启动命令

双卡MoE EP交互推理：

```bash
export LITE_LLAMA_MOE_BACKEND=auto

ASCEND_RT_VISIBLE_DEVICES=4,5 \
python -m torch.distributed.run --nproc_per_node=2 \
  cli_qwen3_moe_tp.py \
  --checkpoints_dir /data/models/Qwen3-30B-A3B/ \
  --page_size 16 \
  --max_seq_len 4096 \
  --max_gen_len 1024 \
  --moe_parallel_mode ep \
  --compiled_model \
  --enable_thinking
```

双卡Continuous Batching服务：

```bash
ASCEND_RT_VISIBLE_DEVICES=4,5 \
python -m torch.distributed.run --nproc_per_node=2 \
  server.py \
  --checkpoints_dir /data/models/Qwen3-30B-A3B/ \
  --port 8213 \
  --page_size 16 \
  --moe_parallel_mode ep \
  --compiled_model \
  --continuous_batching \
  --max_batch_size 32
```

同口径TP/EP Benchmark只需切换：

```text
--moe_parallel_mode tp
--moe_parallel_mode ep
```

## 本地验证

```bash
python -m unittest \
  tests.test_server_batching \
  tests.test_continuous_batching \
  tests.test_decode_p0 \
  tests.models.test_qwen3_moe -v
```

本地CPU测试验证调度状态机、动态Paged KV元数据、Routed-GEMV参考数值、专家权重切分和
两Rank局部专家输出求和。

## Atlas验证要求

本地环境没有Ascend NPU，发布后必须在Atlas 910B3完成：

1. `tests.npu.test_qwen3_moe_gmm`中的Routed-GEMV数值测试；
2. 双卡`--moe_parallel_mode ep`中英文生成正确性；
3. 多并发OpenAI接口请求无串流、死锁和KV泄漏；
4. Graph统计满足`captured > 0`、`replays > 0`且无错误回退；
5. TP与EP相同输入、Batch和Graph配置下的吞吐、显存与通信对比。

## 已知限制

- Continuous Batching首版未实现Chunked Prefill、抢占和优先级；
- 不同Prompt长度分组Prefill，尚未合并为真正No-padding混合Prefill；
- Routed-GEMV Triton Ascend内核必须在目标CANN/torch_npu版本上编译验证；
- EP首版复用现有TP通信组，只支持同一组Rank上的专家切分；
- EP大Prefill批次仍包含本地专家过滤、排序和GMM；
- EP为减少实际专家计算会动态压缩本地assignment，当前NPU Graph可能因此回退Eager；
- VL Server尚未接入Continuous Batching；
- 本版本尚无Atlas性能数据，不声明预测提升。
