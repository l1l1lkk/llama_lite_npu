# v0.0.8rc3 Release Report

Date: 2026-06-22
Branch: `release/0.0.8rc3`

## Summary

`v0.0.8rc3` fixes the remaining TP worker crash in chunked prefill after `v0.0.8rc2`.

`v0.0.8rc2` separated logical sequence length from reserved KV capacity, but TP continuous batching still sent `prefill_chunk` commands to worker ranks before rank 0 had verified the next chunk's KV capacity. If a worker rank hit the capacity failure first, the process exited before rank 0's scheduler could preempt, requeue, or fail the request cleanly.

## What changed

### Rank-0 preflight before TP worker dispatch

`_TpCoordinatedContinuousBackend.prefill_chunk(...)` now calls local backend `prepare_prefill_chunk(...)` before sending the TP control command to worker ranks.

This preparation step:

- allocates the local request id if needed;
- ensures KV capacity for the next chunk;
- raises a scheduler-visible capacity error before any worker enters mirrored execution.

### Per-chunk capacity check

For each chunked-prefill request, the backend now checks capacity for:

```text
target_end + 1
```

before replaying the first token in that chunk. `target_end` is the logical prompt replay end for the current chunk; `+1` reserves the first generated-token slot after prefill completion.

### Clearer capacity errors

Paged KV allocation failures now report:

- request id;
- current logical token count;
- max sequence length;
- remaining free KV pages.

This makes it distinguishable whether a failure comes from sequence-length overflow or real KV page exhaustion.

## Expected performance impact

This is a stability fix. It should not materially improve raw throughput. The expected visible effect is that chunked prefill no longer kills rank 1 with `Paged KV allocation failed for request ...` during incremental replay.

## Validation

Validated locally with:

```bash
python -m unittest tests.test_paged_attention_refcount tests.test_continuous_batching -v
python -m py_compile lite_llama/continuous_batching.py lite_llama/executor/model_executor.py server.py tests/test_continuous_batching.py
```

Server-side validation should rerun the failed chunked-prefill EvalScope command and verify that rank 1 no longer exits inside `extend_paged_requests()`.
