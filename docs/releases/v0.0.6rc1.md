# Lite Llama NPU v0.0.6rc1

- 发布日期：2026-06-12
- 变更类型：Decode热路径功能优化
- 对比版本：v0.0.5rc3

## 目标

本版本不增加模型类型，集中减少Qwen3 TP生成中每个Decode Token重复发生的通信、
Host同步和Python控制开销，同时保持现有采样语义、PagedAttention和NPU Graph架构。

## 主要变更

### Vocab Parallel Sampling

Qwen3 Dense、Qwen3 MoE和Qwen3-VL的LM Head在TP模式下直接返回本地词表分片：

- Greedy采样只交换每个Rank的局部最大Logit和对应全局Token ID；
- Top-P采样使用全局Softmax归一化和有界候选交换；
- 当候选边界无法证明覆盖精确nucleus时，自动Gather完整Logits后采样；
- 需要完整Logprobs的API仍按需Gather全词表。

因此Greedy Decode不再为每个Token传输完整词表Logits，Top-P则优先走有界候选路径，
并以精确回退保证结果语义。

### 设备端Decode状态

Continuous Batching后端为每个Paged KV请求保存：

- 最新采样Token；
- 下一次Decode Position。

worker Rank不再把采样结果复制到Host，也不再根据Python生成历史重建Decode输入。Rank 0
为了生成SSE内容，每个模型Step保留一次批量Token D2H。

### 增量反分词

每个请求维护一个有界后缀解码器。正常情况下只解码最近Token窗口并产生文本增量；
如果Tokenizer边界变化导致后缀无法稳定拼接，则回退完整生成序列解码，优先保证输出正确。

### TP张量控制面

文本Continuous Batching的TP协调命令不再逐Step使用`broadcast_object_list`。新协议包含：

- 固定长度命令头；
- `int64`请求ID、Prompt和长度Payload；
- `float32`Temperature和Top-P Payload。

Prefill广播完整请求初始化信息；Decode和Release只广播稳定的数值控制ID。Legacy单请求
和多模态初始化路径不在逐Token热路径，暂时保留原对象广播。

## 兼容性

- 权重格式不变；
- CLI和OpenAI API参数不变；
- PagedAttention与NPU Graph Bucket策略不变；
- Qwen3 MoE TP/EP的既有执行边界不变；
- 随机采样结果仍由Rank 0产生并广播，防止各Rank RNG状态差异导致KV状态分叉。

## Atlas验证建议

先验证Greedy输出和Graph Replay：

```bash
ASCEND_RT_VISIBLE_DEVICES=4,5 \
python -m torch.distributed.run --nproc_per_node=2 \
  examples/benchmark_tp.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-32B/ \
  --batch_size 4 \
  --prompt_len 128 \
  --max_gen_len 256 \
  --temperature 0 \
  --page_size 16 \
  --compiled_model \
  --warmup 2 \
  --iterations 5
```

再启动Server，通过EvalScope分别测试`temperature=0`与Top-P采样，确认：

1. 输出Token统计正确；
2. TP两个Rank无死锁或Token分叉；
3. Greedy Decode不再出现LM Head完整词表AllGather；
4. NPU Graph capture/replay计数正常；
5. Continuous Batching多请求加入和释放正常。
