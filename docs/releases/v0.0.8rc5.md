# v0.0.8rc5 Release Report

Date: 2026-06-22

## Scope

`v0.0.8rc5` is a correctness/stability release for TP continuous batching. It does not change model kernels or claim a new performance number.

The fix follows the same control-plane principle used by production inference engines such as vLLM: the scheduler emits an execution plan, worker ranks execute that plan, and the driver must not advance mirrored request state until workers have confirmed the command.

## Problem

After chunked-prefill fixes in `v0.0.8rc2` and `v0.0.8rc3`, worker ranks could still fail with errors such as:

```text
RuntimeError: unknown continuous batching control_id: 19
```

or enter shape-divergent decode paths after rank 0 believed a request was ready for decode but a worker rank did not have the same mirrored request state.

## Changes

### Transactional TP command dispatch

`StoreCommandChannel` now returns a command sequence number from `send(...)`. Worker ranks acknowledge each command through TCPStore after successful execution. Rank 0 calls `wait_ack(...)` before marking worker state as mirrored.

This prevents rank 0 from advancing `_worker_known_control_ids` before workers have actually created or updated the corresponding request state.

### Decode state snapshots

Decode commands now use `decode_state` instead of raw `control_id` lists. The command carries:

- `control_id`
- expected logical sequence length before the decode step

Worker ranks validate the expected decode position against their local device-side position before entering model decode. If the state diverges, the error is reported at the TP control-plane boundary instead of surfacing later as an opaque NPU/HCCL failure.

### Worker failure propagation

Worker ranks send negative acknowledgements with the exception message before re-raising. Rank 0 receives that failure through `wait_ack(...)` and fails at the same logical command.

## Validation

Local validation:

```bash
python -m py_compile lite_llama/executor/tp_control.py server.py tests/test_tp_control.py tests/test_server_batching.py
python -m unittest tests.test_tp_control tests.test_server_batching -v
python -m unittest tests.test_continuous_batching -v
```

All tests passed in the development environment.

## Expected behavior

- Unknown worker `control_id` failures should no longer silently appear after rank 0 has advanced scheduler state.
- Decode shape drift should fail early with a `TP worker decode_state mismatch` diagnostic.
- Chunked-prefill TP requests should only enter decode after worker ranks acknowledge prefill/chunk execution.

## Performance note

This release prioritizes correctness. The acknowledgement protocol adds control-plane synchronization around mirrored commands, so it should be profiled before treating it as a final high-performance implementation. A future version can replace TCPStore acknowledgements with a lighter worker-result protocol once the invariants are stable.
