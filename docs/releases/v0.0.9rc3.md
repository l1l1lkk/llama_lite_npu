# v0.0.9rc3 Release Report

Date: 2026-06-23

## Summary

`v0.0.9rc3` fixes a TP synchronization bug in Chunked Prefill. The previous implementation let rank 0 run `prepare_prefill_chunk()` before sending the TP command. That preparation allocated a `model_request_id` for first-chunk requests only on rank 0. Worker ranks still saw the same request as a first chunk.

That caused rank divergence:

```text
rank0: request already has model_request_id -> later/replay chunk path
rank1: request has no model_request_id      -> first chunk packed prefill path
```

Once ranks enter different model paths, HCCL collectives no longer line up. The visible error can appear later as `HcclAllreduce` socket timeout or NPU Graph capture failure, but the root cause is request-state mutation before TP mirroring.

## Fix

- `prepare_prefill_chunk()` no longer allocates new paged requests for first chunks.
- First-chunk KV allocation now happens inside `prefill_chunk()` on every rank.
- Capacity precheck is still kept for existing paged requests / later chunks where `model_request_id` already exists.

## Runtime Expectation

With TP + `--chunked_prefill`, the first chunk should now be mirrored consistently across ranks. If HCCL still fails, the next likely issue is inside the experimental Triton paged chunk kernel itself, not first-chunk state divergence.
