# v0.0.9rc5 Release Report

Date: 2026-06-23

## Summary

`v0.0.9rc5` changes the later-chunk `paged_chunk_flash_attention` path from a fixed conservative tile to runtime tile selection.

This addresses the performance concern that `v0.0.9rc4` always used 16x32 after the 64x64 UB overflow fix. The new path tries larger tiles first and falls back only when the Ascend Triton compiler or runtime rejects a candidate.

## Implementation

Tile candidates are attempted in this order:

```text
64x64 -> 32x64 -> 32x32 -> 16x32 -> 16x16
```

For each process/shape, the first successful tile is cached. Failed tiles are also cached and skipped on later calls.

## Important Diagnosis

The current later-chunk path already feeds only chunk/suffix tokens into model forward. It does not re-project the full prefix. Specifically:

- `continuous_batching.py` builds `flat_tokens` from `context_tokens[start:end]` only.
- `activate_paged_chunk_prefill_batch()` sets `max_actual_q_seq_len = max(chunks)`.
- `paged_chunk_flash_attention()` receives `max_q_len` as chunk length.

Therefore this release does not add a separate chunk-only model forward path; that behavior already exists.

## Expected Behavior

Startup/runtime logs should show a selected tile, for example:

```text
paged_chunk_flash_attention selected tile=32x64 for batch=4 max_q_len=128 head_dim=128
```

If a large tile fails, the runtime logs a compact warning and tries the next smaller tile. Only if all tile candidates fail does it use the torch correctness fallback.
