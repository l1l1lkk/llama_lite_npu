# v0.0.9rc4 Release Report

Date: 2026-06-23

## Summary

`v0.0.9rc4` fixes a runtime crash in Chunked Prefill when the later-chunk `paged_chunk_flash_attention` Triton Ascend kernel fails to compile on Atlas 910B3.

The observed compiler failure was a BiShengIR UB overflow:

```text
ub overflow, requires 1789952 bits while 1572864 bits available
```

This is a kernel tiling/compiler-resource issue, not an HCCL synchronization issue.

## Changes

- Reduced paged chunk FA tile size to a conservative 16x32 shape for 910B3.
- Added a one-shot torch attention fallback if the Triton path fails to compile or launch.
- Preserved the default behavior: Chunked Prefill later chunks still attempt `paged_chunk_flash_attention` first.

## Expected Behavior

When the Triton kernel compiles successfully, the later-chunk path uses paged chunk FA.

If the Triton compiler rejects a shape, the process logs one warning and safely falls back to the torch reference attention for that process instead of terminating the TP worker.

## Validation

- `python -m py_compile lite_llama/kernels/paged_chunk_flashattention.py`
- `python -m unittest tests.test_model_executor_packed_prefill`

## Known Limitations

The fallback path is correctness-first and can be slower. If fallback appears in normal profiling, the next optimization step is to further tune the Triton kernel tiling or split the kernel into smaller resource footprints.
