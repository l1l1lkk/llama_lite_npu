# v0.0.7rc6 Release Report

Date: 2026-06-18

## Summary

`v0.0.7rc6` is a bugfix release for the v0.0.7 KV-cache line. It changes page-aligned partial Prefix Cache reuse from an always-on greedy optimization into an explicit server switch.

## Root cause

`v0.0.7rc5` enabled partial prefix reuse by default. EvalScope random prompts still share a common chat-template prefix, so the server could hit the partial prefix cache and replay the uncached suffix token by token. This preserved correctness but moved work from dense prefill into conservative decode-style replay, causing TTFT regression on random-prompt benchmarks.

Observed symptom:

```text
TTFT rose to ~5.8s while ITL stayed around ~38ms.
```

This indicates decode was not slower; prefill path selection was the regression.

## Changes

- Exact Prefix Cache remains enabled by default for greedy repeated prompts.
- Partial Prefix Cache is disabled by default.
- Added explicit server flag:

```bash
--partial_prefix_cache
```

- TP continuous-batching worker ranks mirror the same partial-prefix-cache switch through module-level runtime state.
- Added regression tests proving default backend construction does not call partial prefix lookup.

## Recommended usage

For normal EvalScope random-prompt throughput tests, do not pass `--partial_prefix_cache`.

For shared-prefix experiments, start the server with:

```bash
--partial_prefix_cache
```

and compare against exact/random prompt baselines.
