# v0.0.14rc1 发布记录

发布日期：2026-07-16

## 版本定位

v0.0.14rc1 是 Qwen3 MoE runtime 边界与 reference correctness 版本。本次变更把
Qwen3 专用实现中的 router、placement 和 routed-expert execution 拆成可解释、可测试的
通用边界，同时保持既有 Qwen3 默认行为。

依据 [`docs/versioning.md`](../versioning.md)，影响主要模型执行链路的通用 MoE 抽象属于
功能级更新，应提升基础版本并从 `rc1` 开始。由于 `0.0.13` 已存在，本次从
`0.0.13rc3` 提升为 `0.0.14rc1`，而不是继续增加为 `0.0.13rc4`。

本版本继续沿用长期分支 `release/0.0.12rc1`，不新建 `release/0.0.14rc1` 分支。最终
发布闭环在全部门禁通过后，以 annotated tag `v0.0.14rc1` 指向获验收的 release commit。

## 架构边界与兼容性

当前最小通用边界包括：

- `RoutingResult`：字段顺序为 `router_logits`、`routing_weights`、
  `selected_experts`，支持属性访问和既有三元 tuple 解包；
- `SoftmaxTopKRouter`：保持
  `linear -> FP32 softmax -> top-k -> optional renorm -> cast back`；
- `ExpertPlacement`：不可变的纯 Python 元数据，表达现有连续 TP intermediate shard 或
  连续 EP expert slice；
- `RoutedExpertExecutor`：承载现有 routed expert 执行主体，不改变 eager、GMM、routed
  GEMV、backend 选择或 all-reduce 位置。

`Qwen3MoeTopKRouter` 和 `Qwen3MoeExperts` 继续作为兼容类型存在。
`Qwen3SparseMoeBlock` 仍构造 Qwen3 兼容类型，以下 state-dict key 保持不变：

```text
gate.weight
experts.gate_up_weight
experts.down_weight
```

权重 layout、constructor/public 属性、`last_router_logits`、输出形状、TP/EP 语义、Graph
eligibility 和服务器参数均未因抽象边界改变。

## 独立 Reference Correctness

CPU reference 是 inference-only 的纯 PyTorch 实现，不导入或调用生产 router、executor、
routing helper、GMM/GEMV helper 或 kernel。router softmax、专家计算和必要累加使用 FP32，
从而避免用被测优化路径验证自身。

reference 明确记录 runtime layout：

```text
router  [E, H]
gate_up [E, H, 2I]
down    [E, I, H]
```

完整模型 checkpoint artifact 为 BF16；加载到本次 runtime 后使用 FP16。因此 D2 主
oracle 的权重语义是：

```text
checkpoint BF16 -> FP16 quantized values -> CPU FP32 math
```

不能把 checkpoint artifact dtype 与 runtime arithmetic dtype 混为一谈。

### 跨 checkout 证据字节契约

发布门在 fresh Windows checkout 中发现：系统级 `core.autocrlf=true` 会在 Git 状态仍为
clean 时把 compact evidence 的 LF blob 物化为 CRLF，从而破坏 manifest 锁定的原始字节
size/SHA256。仓库通过 `docs/validation_data/** text eol=lf` 固定 CSV/JSON（包括 manifest）
的 checkout 字节，使同一提交在 Windows 与 Linux 上保持可复现。该契约属于发布正确性
门，不能用本地 `core.autocrlf` 覆盖来绕过。

## 单卡 NPU 正式回归

在包含 durable regression test 的 commit 上，显式 6 项 NPU MoE suite 分别在物理
NPU 6 和 7 独立执行，两张卡均为 6/6 passed、0 fail/error/skip：

- dynamic routing NPUGraph capture/replay；
- generic runtime boundary 与 Qwen3 compatibility；
- GMM 与 eager local output；
- routed GEMV 的 EP local contribution；
- routed GEMV 与 eager local output；
- validation mode 覆盖每个 sparse block。

generic boundary 与 dynamic Graph 测试均真实执行而非 skip；Graph 测试实际完成
capture/replay。该结果是 correctness 回归，不用于推导吞吐或延迟提升。

## Qwen3-30B-A3B 全模型三角验证

三组使用相同冻结 prompt、seed 42、batch 1、greedy 和 16-token generation：

| 组别 | 并行模式 | MoE backend | Graph | 结果 |
| --- | --- | --- | --- | --- |
| A | TP2 | eager | off | 完成 |
| B | EP2 | eager | off | 完成 |
| C | TP2 | auto | on | 完成，capture 1、replay 15、fallback 0 |

A 与 C 的完整 token 序列和文本 SHA256 exact 相同。A 与 B 的前 15 个 token 相同，只在
0-based token index 15 分叉。该差异没有被直接解释为 EP 缺陷，而是进入 D1/D2 定向
诊断。

## D1 到 D2 的证据链

D1 捕获第 16 次 forward 的 vocabulary logits、逐层 router、rank-local expert output、
post-allreduce、decoder hidden/residual：

- 48/48 层同模式 rank post exact；
- 48/48 层跨模式 post 和 decoder hidden 通过 `rtol=1e-2, atol=1e-2`；
- 唯一 router 顺序差异位于 layer 32 的 expert 104/106，selected set 与 top-k boundary
  均未变化；
- 两个最终候选的 winner margin 与跨模式 logit 扰动均为 `0.03125`；
- layer 37 起部分 residual 未通过 elementwise absolute gate，但 relative L2 约为
  `0.24%`。

由于 D1 当时没有独立 FP32 层 oracle，严格结论为 `INCONCLUSIVE`。

D2 使用 D1 capture、mmap checkpoint 和独立 CPU FP32 数学重建 layer 0、32、37、47，
禁止调用生产 MoE symbol。16 个 rank-local、8 个严格 partition sum、8 个 post、8 个
router selected set 和 128 条 ownership 全部门通过，最终分类为
`BOTH_PATHS_REFERENCE_ALIGNED`。

因此，已有证据支持 TP/EP 两条实现都符合独立 FP32 MoE 语义；最后 token 分叉符合不同
FP16 分解和累加顺序放大近并列 logits 的解释。该结论不要求跨并行模式 token
bit-exact，也不宣称任何一路是绝对 FP32 decoder oracle。

## 分层 Correctness Contract

后续 MoE 改动使用以下分层门：

1. TP/EP rank-local 与 post 对独立 FP32 oracle：`rtol=1e-2, atol=1e-2`；新 dtype 或
   设备必须重新校准。
2. 独立 partition partial sum 对 EXEC_ORACLE：`rtol=1e-5, atol=1e-6`。
3. 同模式 rank post exact、所有 tensor finite、TP coverage 无重叠、EP ownership 唯一
   是硬门。
4. router 锁定 selected set、weights 与 K/K+1 boundary；真实 tie 不锁定 selected
   order。
5. TP eager 与 TP Graph 对冻结 greedy 输入要求 exact。
6. TP 与 EP 在近并列时不要求 token bit-exact，但必须报告候选 logits、winner margin、
   数值扰动和首次差异位置。
7. decoder residual 同时报 raw max/mean、relative L2 和 elementwise close；本次约
   `0.24%` 只是观测值，不固化为通用阈值。

## 已知限制与下一步

- 当前通用边界仅覆盖 Qwen3 softmax top-k routing 与连续 TP intermediate shard/EP
  expert slice。
- 尚未实现 DeepSeek grouped top-k、sigmoid routing、route scale/correction bias、
  shared experts、all-to-all、非连续 expert map、量化 MoE 路径或 MLA。
- 全模型 smoke 仅覆盖一个冻结 prompt 和 16 个生成 token；D2 独立 FP32 oracle 仅覆盖
  四个 MoE 层，不是完整 decoder FP32 证明。
- 本版本没有新增性能结论，不报告吞吐/延迟提升，也不进行 vLLM 或 vLLM-Ascend 性能
  对比。

DeepSeekMoE、shared expert、grouped routing、量化和 MLA 必须在后续阶段分别增加独立
reference、placement/communication 契约和真实 NPU 验证，不能冒充本版本已支持能力。
