# Lite Llama NPU v0.0.4rc1

- 发布日期：2026-06-11
- 目标模型：Qwen3-30B-A3B
- 目标硬件：2 × Atlas 910B3
- 变更类型：MoE Decode性能功能

## 相对v0.0.3rc2的变化

### P3：删除Decode热路径Host同步

PagedAttention的页分配仍由CPU管理，但请求ID在Prefill阶段只转换一次并缓存：

```text
Prefill: b_req_idx -> CPU request id tuple
Decode:  reuse cached ids -> extend page mapping
```

因此Decode不再每个Token执行`b_req_idx.tolist()`。

流式输出本身必须将Token交给CPU tokenizer。本版本复用这次D2H结果判断EOS，删除额外的
`eos_reached.all()`设备同步。请求结束时也使用缓存ID释放Paged KV资源。

### P4：Qwen3 MoE Decode NPU Graph

MoE不再按模型类型静态禁用Graph。启动`--compiled_model`后，执行器按
`(batch_size, 128-token sequence bucket)`尝试Capture：

```text
Attention
 -> Router / TopK
 -> Triton Count / Gather
 -> Argsort / Cumsum
 -> Ascend GMM Gate-Up
 -> Triton SwiGLU
 -> Ascend GMM Down
 -> Triton Scatter
 -> HCCL AllReduce
```

动态专家ID和`group_list`作为Tensor数据在Replay前更新，Shape和存储地址保持固定。

如果任意算子不支持NPUGraph Capture：

1. 当前Batch/Bucket记录为失败Key；
2. 当前请求回退Eager；
3. 后续相同Key不再重复Capture；
4. 不允许使用不完整或错误Graph。

## 可观测性

`examples/benchmark_tp.py`结果末尾新增：

```text
NPU Graph stats: attempts=..., captured=..., replays=..., fallbacks=...
```

只有以下条件满足时，结果才属于Graph路径：

```text
captured > 0
replays > 0
```

如果`captured=0`且`fallbacks>0`，说明当前环境使用Eager回退。

## 验证命令

先验证GMM和动态路由Graph Replay：

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
export LITE_LLAMA_MOE_BACKEND=gmm

ASCEND_RT_VISIBLE_DEVICES=6 \
python -m unittest tests.npu.test_qwen3_moe_gmm -v
```

再运行双卡Benchmark：

```bash
ASCEND_RT_VISIBLE_DEVICES=6,7 \
python -m torch.distributed.run --nproc_per_node=2 \
  examples/benchmark_tp.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-30B-A3B/ \
  --batch_size 4 \
  --prompt_len 128 \
  --max_gen_len 256 \
  --page_size 16 \
  --compiled_model \
  --warmup 2 \
  --iterations 5
```

## 已知限制

- 本地Windows环境无法执行Atlas NPUGraph，最终兼容性以服务器测试为准；
- 当前Graph仍包含`torch.argsort`、动态GMM `group_list`、Triton路由和TP AllReduce；
- 不同CANN/torch_npu版本可能只支持其中部分算子Capture；
- Capture失败会安全回退，因此“程序能运行”不等于“Graph已经生效”；
- 本版本不声明性能提升幅度，实测后写入性能历史记录。
