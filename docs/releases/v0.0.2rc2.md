- 变更类型：正确性Bug修复

## 相对v0.0.2rc1的更新

修复MoE专家融合Gate/Up输出在SwiGLU Triton内核中的行跨度错误。

融合投影输出经过`chunk(2, dim=-1)`后，Gate和Up是非连续视图。它们的行跨度仍等于完整Gate/Up宽度，而SwiGLU输出的行跨度只等于单个分支宽度。旧内核错误地使用输出行跨度读取两个输入，导致同一专家处理多个Prompt Token时从第二行开始读取错误地址。

该错误首先污染Prefill隐藏状态和KV Cache，最终表现为模型能够生成流畅文本，但回答与用户问题无关。

## 修复方式

SwiGLU内核由共享一个行跨度：

```text
row_stride
```

改为分别接收：

```text
a_row_stride
b_row_stride
c_row_stride
```

内核按各张量真实stride进行寻址，同时兼容Dense MLP连续张量和MoE融合投影非连续视图。

目标服务器需要执行：

```bash
ASCEND_RT_VISIBLE_DEVICES=6,7 \
python -m torch.distributed.run --nproc_per_node=2 \
  cli_qwen3_moe_tp.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-30B-A3B/ \
  --page_size 16 \
  --max_seq_len 4096 \
  --max_gen_len 64 \
  --temperature 0 \
  --disable_thinking \
  --no_compiled_model
```

使用`你是谁`验证首个生成Token和完整回答是否恢复正常。无需重新转换权重。

## 已知限制

- 暂不支持MoE Decode NPU Graph；
- 尚未接入Ascend Grouped MatMul；
