# v0.0.8rc8 Release Report

Date: 2026-06-22

## Summary

`v0.0.8rc8` fixes a continuous-batching packed-prefill crash that could happen even when `--chunked_prefill` was disabled.

The fix follows the vLLM scheduler principle more closely: scheduling is bounded by a token budget, not only by request count. The backend also validates the effective packed-prefill size before model forward and splits oversized work into safe micro-batches.

## Root Cause

Without chunked prefill, the scheduler could still admit multiple long prompts into one packed-prefill forward. Qwen3 Q/K RMSNorm receives tensors shaped roughly as:

```text
[total_prefill_tokens, local_q_heads, head_dim]
```

The current Triton RMSNorm kernel launches one program per flattened row:

```text
grid_rows = total_prefill_tokens * local_q_heads
```

When `grid_rows >= 65536`, Triton raises:

```text
RuntimeError: grid should be less than 65536
```

This was a scheduler shape-control bug, not a chunked-prefill-only bug.

## Changes

- `ModelExecutor` now derives `max_prefill_tokens` from the local Q-head count:

```text
safe_prefill_tokens = floor(60000 / local_q_heads)
```

- `ContinuousBatchScheduler` now uses the backend-derived `max_prefill_tokens` when the user does not pass `--max_prefill_tokens`.
- `ContinuousBatchModelBackend.prefill()` now splits packed prefill into budget-safe micro-batches before calling `executor.forward(...)`.
- A single prompt larger than the safe packed-prefill budget falls back to the existing incremental prefill path. This is slower but avoids kernel launch failure.
- Server startup logs now print the effective `max_prefill_tokens` value.

## Expected Impact

- Prevents Triton grid overflow in mixed-length packed prefill.
- Keeps common short/mid prompt packed prefill fast.
- May reduce throughput for very long prompt batches because large packed prefill is split into multiple safe forwards.
- Does not change decode NPU Graph behavior.

## Verification

Local CPU/unit verification:

```bash
python -m unittest tests.test_continuous_batching -v
```

Targeted regressions:

- scheduler defaults to backend-derived prefill token budget;
- backend splits mixed-length packed-prefill batches by token budget.
