## 版本定位

v0.0.15rc2 是 v0.0.15rc1 DeepSeek V2/V3 MoE 组件正确性版本的发布规范与跨平台
测试契约修订。它不改变 router、routed/shared expert、checkpoint reader、Graph policy
或 NPU 执行逻辑，也不增加新的性能结论。

本版本将此前依赖流程惯例的发布分支规则写入仓库规范：每个版本使用独立的
`release/<VERSION>` 分支和 `v<VERSION>` annotated tag。feature 分支只承载开发过程，
不能代替正式发布分支；新版本也不能继续推进旧版本 release 分支。

## 相对 v0.0.15rc1 的变化

### 独立发布分支与 Tag

- `0.0.15rc2` 的唯一正式发布分支是 `release/0.0.15rc2`；
- 唯一正式 tag 是 annotated `v0.0.15rc2`；
- branch head、tag peeled commit、`VERSION`、本地/GitLab ref 与已验证服务器 checkout
  必须一致；
- tag 发布后不可移动，release 分支也不再推进；后续修订必须使用新 RC；
- 历史 tag 保持不可变，历史分支不一致需要单独审计，不能在普通发布中 force 改写。

### Windows 冻结源码校验

v0.0.15rc1 在 Git canonical blob 和已验收工作树中通过全部 DeepSeek CPU contract；但在
系统 `core.autocrlf=true` 的旧 Windows checkout 中，五个冻结 Python 文件可能被物化为
CRLF。测试此前直接对工作树原始字节做 SHA256，因而会把纯行尾差异误判为源码漂移。

v0.0.15rc2 同时采取两层修订：

1. 对冻结 DeepSeek reference/contract 文件增加窄范围 `text eol=lf` checkout 契约；
2. 冻结源码测试在 SHA256 前只规范化 CRLF 为 LF，仍对完整源码内容进行哈希，任何非行尾
   变化继续 fail-closed。

原阶段范围测试曾把既有测试文件永久列为“相对当前 HEAD 不可修改”，从而会拒绝后续经过
授权的测试契约修订。本版本将这两组阶段范围门收窄为生产与Qwen兼容源码；独立
reference、router、block、component、checkpoint和权重布局继续由各自完整功能测试及
权重契约中的源码哈希覆盖。`moe.py` 的冻结期待值同时改为 canonical LF Git blob SHA，
避免沿用旧工作树的混合行尾指纹。

这不是通过关闭 `core.autocrlf` 或修改本地 Git 配置绕过测试；仓库规则和测试语义均随
版本提交，适用于 fresh checkout 与既有 Windows worktree。

## 保持不变的正确性证据

本版本不重跑或改写 v0.0.15rc1 的硬件结论：

- DeepSeek V2/V3 × FP16/BF16 component suite 在物理 Atlas 910B3 NPU 6 上通过 2/2、
  skip 0；
- Qwen MoE 保护套件在物理 Atlas 910B3 NPU 7 上通过 6/6、skip 0；
- DeepSeek decode Graph 仍显式 fail-closed；
- 独立 CPU FP32 reference 仍是 router、routed/shared expert 与组合输出的数值 oracle。

## 已知限制

- 仅支持 DeepSeek V2/V3 MoE component，不是完整 DeepSeek Model/CausalLM；
- MLA、attention、KV/RoPE、完整 decoder 与完整模型 loader 尚未实现；
- W8A8、量化 kernel、all-to-all、EPLB 和非连续 expert map 尚未实现；
- TP2/EP2 真实 NPU collective 与 DeepSeek Graph correctness 尚未验证；
- 本版本没有新增 benchmark，不声明吞吐、TTFT、TPOT、时延或显存变化。
