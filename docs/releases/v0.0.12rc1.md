# v0.0.12rc1 Release Report

## 版本定位

v0.0.12rc1 聚焦调度与 Prefill 策略。之前 Chunked Prefill 在短/中等 prompt 下容易比 packed prefill 慢，因此本版本将服务端默认策略改为自适应：短 prompt 继续走 packed prefill，只有超过阈值的长 prompt 才进入 chunked prefill。

## 主要更新

- 新增 `--chunked_prefill_policy {adaptive,always}`。
- 新增 `--chunked_prefill_min_tokens`，默认 `2048`。
- `adaptive` 策略下：
  - prompt/context token 数低于阈值时走 packed prefill；
  - 达到阈值时走 chunked prefill；
  - 已进入 chunked prefill 的请求继续按 chunk 推进。
- `always` 策略保留旧行为，用于强制 chunked prefill 测试。
- 调度器支持同一 tick 内混合处理 packed prefill 和 chunked prefill。

## 为什么这样做

现有测试表明，当前 Qwen3-32B 的常见 EvalScope 输入长度下，packed prefill 明显优于 chunked prefill。Chunked prefill 更适合长 prompt、并发 decode 需要抢占计算窗口、或未来实现更完整的 prefill/decode 混排时使用。因此默认自适应比“一开 chunked 就全量分块”更稳。

## 推荐启动命令

短/中 prompt 性能测试建议不开 chunked prefill：

```bash
ASCEND_RT_VISIBLE_DEVICES=6,7 \
python -m torch.distributed.run --nproc_per_node=2 server.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-32B/ \
  --host 0.0.0.0 \
  --port 8213 \
  --max_seq_len 4096 \
  --page_size 16 \
  --compiled_model \
  --continuous_batching \
  --max_batch_size 32
```

长 prompt 或压力测试可开启自适应 chunked prefill：

```bash
ASCEND_RT_VISIBLE_DEVICES=6,7 \
python -m torch.distributed.run --nproc_per_node=2 server.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-32B/ \
  --host 0.0.0.0 \
  --port 8213 \
  --max_seq_len 4096 \
  --page_size 16 \
  --compiled_model \
  --continuous_batching \
  --max_batch_size 32 \
  --chunked_prefill \
  --prefill_chunk_size 512 \
  --chunked_prefill_policy adaptive \
  --chunked_prefill_min_tokens 2048
```

如需复现旧版本强制分块行为：

```bash
  --chunked_prefill \
  --prefill_chunk_size 512 \
  --chunked_prefill_policy always
```
