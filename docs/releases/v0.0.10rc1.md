# v0.0.10rc1 Release Report

Date: 2026-06-23

## Summary

`v0.0.10rc1` moves the optimization focus back from Chunked Prefill to the current production-relevant path: packed prefill plus decode.

For the current Qwen3-32B 2-card Atlas 910B3 benchmark shape, Chunked Prefill has low return because prompts are short to mid length and packed prefill is already efficient. This release therefore cleans hot-path host synchronization and worker-only host copies before considering merge toward the main branch.

## Changes

### Decode hot path

- TP worker ranks no longer perform per-token decode-state validation by default.
- The previous validation remains available via:

```bash
export LLAMA_LITE_NPU_VALIDATE_TP_DECODE_STATE=1
```

This keeps debug capability without forcing `.cpu().item()` synchronization on every worker decode step.

### Worker prefix-cache host copies

- Worker backends use `return_host_tokens=False`. They do not need host token IDs for SSE output or prefix-cache storage.
- Prefix-cache storage remains active on rank 0, where host tokens are already needed for request output.

### Chunked Prefill note

Chunked Prefill remains implemented and testable, but the current recommendation is to keep it disabled for short/mid prompt benchmark runs unless the workload has long prompts or requires prefill/decode interleaving fairness.

```bash

python -m torch.distributed.run --nproc_per_node=2 server.py \
  --checkpoints_dir /data/liuke/llama_lite_npu/my_weight/Qwen3-32B/ \
  --host 0.0.0.0 \
  --port 8213 \
  --page_size 16 \
  --max_seq_len 4096 \
  --compiled_model \
  --continuous_batching \
  --max_batch_size 32
```

For the current workload, do not enable `--chunked_prefill` unless specifically testing long-prompt scheduling behavior.
