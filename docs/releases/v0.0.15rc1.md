# v0.0.15rc1 发布记录

发布日期：2026-07-18

## 版本定位

v0.0.15rc1 是 DeepSeek V2/V3 MoE 组件兼容与单卡 NPU correctness 版本。它在
v0.0.14rc1 已建立的通用 `RoutingResult`、router、placement 和 routed-expert executor
边界上，增加 grouped routing、shared expert、权重适配、官方字段配置和有界单层
checkpoint 读取。

依据 [`docs/versioning.md`](../versioning.md)，这组变更扩展了核心模型执行组件，属于功能级
更新，因此版本从 `0.0.14rc1` 提升为 `0.0.15rc1`。

“组件兼容”是本版本的严格能力边界：生产代码可以构造和严格装载单层 DeepSeek V2/V3
MoE block，并对独立 reference 完成 CPU/NPU 数值验证；它不表示完整 DeepSeek 模型、
CausalLM 或端到端生成已经接入。

## 功能提交

本版本包含七个按依赖顺序组成的 feature commit：

- `1890b509`：建立 DeepSeek V2/V3 独立 CPU FP32 reference 与行为契约；
- `52a2eeaf`：增加生产 grouped top-k router，保持 `RoutingResult` 与 Qwen ABI；
- `025301a8`：增加 shared expert placement、MLP 与 DeepSeek MoE block；
- `40b8f8a7`：增加 HF→canonical 权重转换与 routed/shared runtime layout helper；
- `ff0866b8`：增加官方字段驱动的组件配置、MoE layer factory 与 state adapter；
- `75c5e68e`：增加有界单层 safetensors checkpoint reader；
- `4c51eb88`：增加 durable DeepSeek NPU component gate 与 Graph fail-closed policy。

完整发布提交使用这些 commit 的完整Git历史；短SHA仅用于文档可读性。

## 独立 CPU FP32 Reference

reference 是 inference-only 的纯 PyTorch CPU 实现，不导入生产 router、executor、
checkpoint adapter、GMM/GEMV helper 或设备 kernel。它覆盖：

- DeepSeek V2：`softmax + group_limited_greedy`；
- DeepSeek V3：`sigmoid + noaux_tc`；
- 先选择 top groups，再在保留组中选择 token top-k experts；
- correction bias 只进入 selection score；
- combine weight 始终从未加 bias 的原始 score gather；
- optional top-k normalization 与 routed scaling factor；
- routed SwiGLU、shared SwiGLU 与二者相加；
- world-size-one、TP intermediate partial 和 replicated-token EP ownership；
- 空 token、tie 集合语义、极端有限 logits 与非法配置 fail-closed。

reference 对V3全零归一化分母和缩放后非有限weights显式拒绝，不用epsilon、clamp或fallback
掩盖异常。生产热路径只覆盖已验证的有效数值域，不通过host同步复制这些reference检查。

## V2/V3 Grouped Router

`DeepSeekGroupedTopKRouter`继续返回：

```text
RoutingResult(router_logits, routing_weights, selected_experts)
```

其中 `selected_experts` 是global expert ID并保持`int64`；router内部selection数学使用
FP32。V3 `e_score_correction_bias`保持FP32，只影响expert selection；最终combine仍使用
原始sigmoid score。公开tuple ABI没有增加diagnostic字段，Qwen3 compatibility type、
state-dict keys和默认行为保持不变。

DeepSeek-V4的`sqrtsoftplus`和static-hash routing不属于该策略，遇到这些配置时明确拒绝，
不回退为V3路由。

## Routed 与 Shared Expert Block

`DeepSeekMoeBlock`由以下三个独立组件组成：

```text
DeepSeekGroupedTopKRouter
  -> RoutedExpertExecutor
  +  SharedExpertMLP
```

routed expert复用现有连续TP/EP placement和eager/GMM/routed-GEMV执行边界。shared expert
拥有独立的intermediate placement：world-size-one使用完整intermediate；TP按连续
intermediate slice计算partial并只reduce一次；EP每rank复制完整shared expert且不做EP
routed all-reduce。block只把两条已经明确ownership的输出相加，避免double reduce或
world-size倍增。

当前EP语义是token replicated、global routed expert连续slice并在末端组合，不是DeepSeek
原生all-to-all、EPLB或非连续expert map。

## HF → Canonical → Runtime 权重布局

官方风格HF MoE key先转换为canonical state：

```text
gate.weight                         [E, H]
gate.e_score_correction_bias        [E]       # V3, FP32
experts.gate_up_weight              [E, 2I, H]
experts.down_weight                 [E, H, I]
shared_experts.gate_up_weight       [2Is, H]
shared_experts.down_weight          [H, Is]
```

runtime helper再按world-size-one、TP或EP转换为block需要的layout。routed TP沿intermediate
连续切片，routed EP沿global expert连续切片；shared TP沿intermediate切片，shared EP保持
完整复制。测试使用独立构造的expected stack/cat/slice验证布局，而不是用converter验证自身。

转换器验证layer、expert numeric order、shape、dtype、device和key集合。`consume=True`
只有在全部目标层验证和转换成功后才统一删除源key，失败时不产生partial pop。

## 官方字段驱动的组件边界

`DeepSeekMoeConfig`冻结并校验官方DeepSeek V2-Lite/V3字段，包括H、层数、dense/routed/
shared intermediate、expert数、top-k、score function、group策略、route scale和MoE layer
schedule。`model_type`与`architectures`必须精确配对；required source fields缺失、alias与
canonical冲突、V2/V3策略错配和V4字段均fail-closed。

组件factory只为命中官方0-based MoE schedule的layer构造`DeepSeekMoeBlock`。它没有加入
完整模型`CONFIG_CLASS_MAP`，也不构造dense MLP、attention、embedding、LM head或采样器，
从而避免把单层组件能力误表述为完整模型支持。

## 有界单层 Safetensors Reader

checkpoint reader支持两种明确布局：

- 目录内唯一单文件`safetensors`；
- 唯一标准`model.safetensors.index.json`分片索引。

它每次从同一resolved root重新读取并严格审计`config.json`，拒绝duplicate JSON key、
配置provenance漂移、行为覆盖型配置子类、非标准index、多文件无index、缺失required key
和非法tensor。config、index、single-file discovery以及indexed shard均有root containment
检查，拒绝绝对路径、drive路径、`..` traversal和resolve后逃逸。

reader只打开目标MoE layer相关shard，每个相关shard最多一次，并只调用目标required key的
`get_tensor`。输出是单层CPU canonical state；普通权重保持源dtype，V3 bias规范化为FP32。
它不是完整checkpoint loader，index JSON仍整体加载，单层源tensor与canonical copy仍可能
同时占用内存。

## 单卡 Atlas 910B3 硬件门

### DeepSeek component：physical NPU 6

包含durable测试的提交上，唯一正式命令为：

```bash
ASCEND_RT_VISIBLE_DEVICES=6 \
LITE_LLAMA_MOE_BACKEND=gmm \
LITE_LLAMA_MOE_VALIDATE=1 \
python -m unittest tests.npu.test_deepseek_moe -v
```

原始unittest命令exit code `0`，`Ran 2`，2 passed、0 failed/error/skip。硬件case覆盖
DeepSeek V2/V3 × FP16/BF16，selected IDs exact，router/routed/shared/full block通过
`rtol=1e-2, atol=1e-2`，V3 correction bias保持selection-only，真实GMM/grouped路径及
validation对照调用数符合合同。运行PID被physical NPU 6监控捕获，结束后设备恢复空闲。

封存证据`SHA256SUMS` self SHA：

```text
d9653d06d66de41a2a4207aada348c357054be138c276abd808825dee914d316
```

repo外runner在unittest成功之后检查了错误的测试类名，因而保留失败终态。该runner没有被
改写为GO；硬件通过结论来自原始命令exit、Ran/OK、0 skip、negative scan与PID映射。

## Graph 策略

完整DeepSeek decoder/CausalLM与decode Graph correctness尚未验证，因此
`supports_decode_graph`对`deepseek_v2`和`deepseek_v3`显式返回false。Qwen dynamic
NPUGraph保护测试成功不能外推为DeepSeek Graph pass。该策略是fail-closed能力边界，
不是Graph性能或正确性结论。

NPU测试必须在具备`torch_npu` GMM的目标卡上显式运行；CPU环境中的透明skip不是硬件pass。
设备dtype容差`rtol=1e-2, atol=1e-2`只适用于当前冻结case，不应外推为所有模型、shape
或dtype的通用阈值。

## 已知限制

- 仅支持DeepSeek V2/V3 MoE component compatibility，不是完整DeepSeek Model/CausalLM。
- MLA、attention、KV cache、RoPE、完整decoder、完整loader和端到端生成未实现。
- W8A8、W4A8、FP8与其他量化kernel未实现，也不存在forward时反量化的性能主张。
- EP仅为replicated-token连续expert slice；没有all-to-all、EPLB或非连续expert map。
- 真实TP2/EP2 NPU collective尚未验证。
- DeepSeek Graph correctness未验证，策略保持fail-closed。
- DeepSeek-V4 `sqrtsoftplus`与static-hash routing不支持。
- 本版本没有新增性能benchmark，不报告吞吐、TTFT、TPOT、时延或显存结论。
