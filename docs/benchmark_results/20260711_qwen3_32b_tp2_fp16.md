## 环境

- 模型与 checkpoint：`/data/liuke/llama_lite_npu/my_weight/Qwen3-32B`
- 硬件：2 × Atlas 910B3，`ASCEND_RT_VISIBLE_DEVICES=6,7`，TP=2
- 执行精度：FP16。checkpoint `config.json` 标记为 BF16，但模型加载器会转换并断言 FP16 参数和 FP16 KV；环境快照同时保留两层事实。
- CANN/驱动版本标识：`26.0.rc1`
- PyTorch / torch_npu：`2.7.1 / 2.7.1`
- triton-ascend：`3.2.0`
- EvalScope：`1.7.1`
- 服务配置：最大序列长度 4096、page size 16、最大 batch 32、continuous batching 与 decode priority 开启；partial prefix cache 和 chunked prefill 关闭。
- 数据集：EvalScope random，seed 42，每个正式 run 使用确定且唯一的 dataset offset；流式 greedy，`temperature=0`、`top_p=1`。
- 输入校准：EvalScope prompt 106 经 Qwen3 chat template 后为服务端 128 input tokens。

权威环境快照位于 Git bundle 的 `environment/` 目录。

## Graph-on 主基线

每行是 3 个正式 run 的算术平均值。每个 worker 先做 2 个 warmup 请求，EvalScope 客户端汇总不包含 warmup。完整精度保留在 bundle 的 `aggregate.csv`。

| Prompt / max output | 并发 | 正式请求 | 输入严格有效 | 输出严格 256 | Client output tok/s | Client TTFT | Client TPOT | Client ITL | Client QPS | Server queue wait | Graph replay / fallback |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 128 / 256 | 1 | 36 | 3/3 | 2/3 | 25.5572 | 405.10 ms | 37.67 ms | 37.53 ms | 0.10127 | 0.49 ms | 10583 / 0 |
| 128 / 256 | 4 | 72 | 3/3 | 1/3 | 45.5166 | 10977.79 ms | 41.92 ms | 41.78 ms | 0.17977 | 9847.89 ms | 12240 / 0 |
| 128 / 256 | 8 | 144 | 3/3 | 3/3 | 77.3994 | 12494.27 ms | 53.42 ms | 53.32 ms | 0.30233 | 10316.61 ms | 12240 / 0 |

Graph-on 共 252 个正式请求，全部成功。当前服务请求 schema 会忽略 EvalScope 的 `min_tokens` 扩展，因此随机 prompt 可能在 `max_tokens=256` 前生成 EOS。c1 第 3 轮平均输出 245.4167；c4 第 1、2 轮分别为 253.9583 和 249.5417。这些 run 保留在原始记录中并标记为非严格结果，没有伪装成固定长度数据。本报告不抄录 percentile；如需分析，应直接读取对应 run 的 `benchmark_percentile.json`。

## NPU Graph on/off 消融

Graph-off 使用相同 checkpoint、seed、prompt 映射、greedy、调度器参数和 NPU。为控制 eager 耗时，c1 每轮 3 个正式请求，c4 每轮 8 个正式请求；两档仍各完成 3 个正式 run，并保持每 worker 2 个 warmup。

| Graph | Prompt / output | 并发 | 正式请求 | 严格 run | Client output tok/s | Client E2E | Client TTFT | Client TPOT | Client ITL | Server queue wait | Replay / fallback |
|---|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| off | 128 / 256 | 1 | 9 | 3/3 | 5.4356 | 47.098 s | 403.34 ms | 183.12 ms | 182.40 ms | 0.42 ms | 0 / 0 |
| off | 128 / 256 | 4 | 24 | 3/3 | 10.5776 | 90.573 s | 42436.40 ms | 188.77 ms | 188.12 ms | 41744.40 ms | 0 / 0 |

Graph-off 生命周期始终为 capture=0、replay=0、fallback=0；Graph-on 有 replay 且 fallback=0。这里不计算严格加速比，因为 Graph-on c1/c4 包含提前 EOS 的 run，且 Graph on/off 正式请求数不同。该表只作为执行路径证据。
