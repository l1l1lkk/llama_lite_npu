# v0.0.7rc1 Scheduler and KV Engine Refactor Design

## Goal

Build the first scheduler/KV-engine layer above the existing model executor. This release focuses on safe, testable control-plane improvements rather than changing model math.

## Scope

v0.0.7rc1 implements three foundations:

1. Token-budget admission for continuous batching.
2. KV metadata primitives for block reference counting and prefix-cache lookup.
3. A chunked-prefill planning/configuration entry point, disabled by default until the model backend supports partial prefill execution safely.

## Non-goals

- No vLLM-level preemption yet.
- No production prefix-cache KV reuse in model execution yet.
- No chunked-prefill execution that writes partial KV to the live cache yet.
- No new performance numbers without Atlas 910B3 measurement.

## Design

### Token-budget scheduler

The current scheduler admits requests only by request count. v0.0.7rc1 adds optional token budgets:

- `max_prefill_tokens`: maximum prompt tokens admitted into one scheduler tick.
- `max_decode_tokens`: maximum active decode rows executed in one scheduler tick.

If a single pending request is larger than `max_prefill_tokens`, the scheduler may admit it alone. This avoids starvation for long prompts while still preventing multiple long prefills from entering one tick.

### KV metadata engine

A new CPU-side metadata module tracks logical KV blocks independently from the NPU KV tensor storage:

- `KVBlockRefCounter` owns block ids and reference counts.
- `PrefixCache` maps full token blocks to block ids and finds the longest reusable prefix.
- Prefix matching is block-aligned and deterministic.

This is intentionally separate from `KVCacheMemoryManager` for v0.0.7rc1. The existing NPU allocator remains the source of live KV memory truth.

### Chunked prefill planning

`ChunkedPrefillPlanner` splits a prompt into fixed-size chunks. The scheduler/backend can receive this configuration, but execution remains disabled by default. This gives the next release a tested interface for mixed decode/prefill scheduling without silently changing correctness today.

## Correctness rules

- Existing non-continuous and continuous-batching behavior must remain compatible when budgets are unset.
- Token-budget admission must preserve FIFO order and avoid starvation for one oversized request.
- KV refcounts must never become negative.
- Prefix cache must only return complete block matches.

## Testing

- Unit tests for token-budget admission.
- Unit tests for decode budget fairness.
- Unit tests for KV refcount acquire/release behavior.
- Unit tests for longest block-aligned prefix matching.
- Unit tests for chunked prefill planning.
